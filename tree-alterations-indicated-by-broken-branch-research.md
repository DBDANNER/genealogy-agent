# Tree Alterations Indicated by Broken-Branch Research

**Analytical overlay — not an edited pedigree**  
Last updated: 15 September 2026

## Purpose

This file records pedigree and vital-fact alterations indicated by the broken-branch research without changing the project's mini-trees or FamilySearch during the research cycle.

It serves two purposes:

1. **Analytical overlay:** downstream work such as migration, chronology, geography, DNA interpretation, and lineage summaries should use these research-qualified corrections where relevant rather than silently relying on inherited tree assertions that the broken-branch investigations have weakened or contradicted.
2. **Final reconciliation queue:** after the broken-branch cycle and later synthesis work are complete, this file can be reviewed item by item to decide what actual tree edits, if any, should be made.

This file does **not** convert strongly supported reconstructions into established genealogy. Every override retains its evidence grade.

## Operating rule

For downstream analysis:

- keep the recorded mini-tree unchanged;
- apply this file as an explicit overlay;
- distinguish **established**, **strongly supported**, **plausible**, and **unknown** propositions;
- never fill an unknown parent merely to keep a continuous pedigree;
- where a structural correction is strongly supported but the exact person is not proved, model the missing generation as an analytical placeholder rather than inventing a fully identified ancestor.

For eventual tree editing:

- return to the relevant canonical case report;
- verify that no later investigation changed the conclusion;
- make edits only in a deliberate reconciliation pass.

## How to use this during final-stage analysis

For migration or geographic analysis, treat the mini-tree as the base graph and this document as an override layer.

Examples:

- A migration path should not be generated from an unsupported parent simply because that parent appears in FamilySearch.
- The Morehouse path should include an analytically inserted Southampton generation, but that generation should be labeled strongly supported rather than established.
- Unsupported exact birth/death points such as Nathaniel Peck's inherited 1720/1759 dates should not be used to create false geographic precision.
- A surname correction such as Anna “Snow” should alter lineage labels in analysis even though the underlying mini-tree has not yet been edited.

The goal is to let later synthesis use the best current evidence **without erasing the distinction between research conclusion and executed pedigree change**.
